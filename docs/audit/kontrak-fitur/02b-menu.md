## Risiko hilang diam-diam

1. **Gerbang sesi + redirect ke /login pada halaman daftar menu** — Kalau rebuild memakai createClient() sendiri per komponen, cache() hilang dan auth query berlipat; kalau redirect dilepas, halaman render kosong tanpa proteksi.
2. **Urutan default daftar menu: sort_order lalu created_at** — nullsFirst:false sangat mudah hilang saat query ditulis ulang; efeknya menu baru meloncat ke atas dan urutan hasil drag pengguna terlihat rusak.
3. **Pengambilan data paralel menu + resep (Promise.all)** — Rebuild sering memecah jadi dua await berurutan; halaman jadi ~2x lebih lambat tanpa gejala visual apa pun.
4. **Turunan status resep per menu (none / ready / low) dengan aturan 'low menang'** — Logika agregasi 'low menang' (baris 59) mudah tersederhanakan jadi 'nilai terakhir menang' saat ditulis ulang, dan menu yang sebenarnya kurang stok akan tampil hijau.
5. **Join Inventory_Items yang bisa berbentuk objek atau array** — Normalisasi array/objek ini tidak kelihatan di UI; kalau hilang, halaman bisa TypeError di produksi tergantung bentuk respons PostgREST.
6. **Pesan error server dalam Bahasa Indonesia saat gagal memuat menu / resep** — Ada test khusus untuk ini (tests/menu-page-inventory-errors.test.ts). Rebuild yang menyatukan jadi satu pesan generik akan memecah test dan menghilangkan diagnosa.
7. **Penghitung '{n} item terdaftar' di header** — Mudah tercampur dengan counter hasil pencarian saat komponen digabung; dua angka ini punya arti berbeda.
8. **Empty state daftar menu dengan CTA sendiri** — Dua empty state berbeda ini sering digabung jadi satu saat rebuild, padahal CTA-nya dan pesannya berbeda.
9. **Tata letak tombol header responsif (mobile stacked, primary di atas)** — flex-col-reverse itu keputusan sadar (primary di atas di mobile). Rebuild biasanya memakai flex-col biasa dan urutannya terbalik tanpa disadari.
10. **Skeleton loading khusus halaman menu** — loading.tsx adalah file terpisah yang gampang terlupakan saat rebuild; hilangnya tidak memicu error apa pun, hanya layar kosong/kedip saat navigasi.
11. **Meteran jatah AI di atas daftar menu** — Aturan 'null berarti sembunyikan, bukan tampilkan nol' dan ambang 20% (Math.max(1, ceil(quota*0.2))) hanya ada di kode. Rebuild yang menampilkan '0 / 0' saat error akan membuat pemilik kafe panik tanpa alasan.
12. **Pencarian menu di toolbar tabel (nama + kategori)** — Pencocokan ke kategori (bukan hanya nama) dan urutan sort-lalu-filter mudah hilang; tombol clear beserta aria-label/title-nya juga sering tidak dibawa.
13. **Sorting kolom tiga-tahap: asc -> desc -> kembali ke urutan manual** — Tahap ketiga (kembali ke manual) sangat tidak biasa dan hampir pasti hilang di rebuild — padahal itulah satu-satunya cara user mengaktifkan kembali drag-to-reorder.
14. **Aturan perbandingan sorting per kolom (locale Indonesia, rank khusus)** — Rank inventory (low paling atas) adalah keputusan produk: pemilik ingin melihat masalah stok dulu. localeCompare('id') juga mudah tergantikan a<b biasa yang salah untuk huruf besar/kecil.
15. **Indikator arah sort di header kolom** — row-reverse khusus untuk kolom rata-kanan adalah detail visual kecil yang hampir pasti hilang; hasilnya panah melayang di posisi salah.
16. **Drag-and-drop mengatur urutan menu (HTML5 drag events)** — Kombinasi ref + state untuk drag id, guard from===to, dan pemakaian array rows (bukan display) sebagai sumber index — semuanya mudah salah di rebuild dan menghasilkan urutan yang acak.
17. **Penguncian drag saat sedang di-sort atau sedang mencari** — Ini penjagaan integritas data yang tidak kelihatan. Kalau hilang, user bisa menyeret pada daftar tersaring dan urutan menu di halaman pelanggan jadi kacau tanpa peringatan apa pun.
18. **Indikator 'Menyimpan' / 'Tersimpan' urutan yang kedaluwarsa sendiri** — Tiga status berbeda berbagi satu slot layout. Rebuild biasanya menyisakan satu saja, dan tombol 'Urutan manual' — satu-satunya jalan pintas kembali ke drag — ikut hilang.
19. **Teks bantuan toolbar yang berubah menurut mode** — Kalimat 'klik judul lagi untuk reset' adalah satu-satunya petunjuk untuk siklus sort tiga-tahap. Kalau hilang, fitur reset jadi tidak dapat ditemukan.
20. **Sinkronisasi ulang urutan lokal saat server mengirim data baru** — Kalau dependency diganti [menus] biasa, setiap refresh akan membuang urutan lokal user di tengah interaksi — bug yang sulit ditelusuri.
21. **Dua representasi data (tabel desktop / kartu mobile) lewat ResponsiveDataView** — Kalau rebuild memakai 'hidden lg:block' saja selamanya, elemen non-aktif tetap ada di DOM dan menangkap fokus keyboard — regresi aksesibilitas yang tidak terlihat mata.
22. **Tabel menu: scroll horizontal dengan lebar minimum 720px** — min-width + overflow container mudah hilang; akibatnya seluruh halaman dashboard bisa digeser horizontal di laptop kecil.
23. **Thumbnail menu dengan fallback ikon** — Ukuran berbeda antara tabel dan kartu, dan alt='' yang disengaja, mudah hilang; alt yang diisi nama menu justru membuat screen reader membaca nama dua kali.
24. **Nama menu terpotong dengan tooltip nama penuh** — Atribut title adalah satu-satunya cara membaca nama penuh tanpa membuka halaman edit; sangat mudah tertinggal.
25. **Perbedaan label kategori kosong antara tabel dan kartu** — Perbedaan ini terlihat seperti inkonsistensi dan akan dirapikan otomatis saat rebuild — padahal ruang di tabel memang sempit.
26. **Format harga Rupiah id-ID tanpa desimal + tabular-nums** — tabular-nums dan locale id-ID sering diganti toLocaleString default atau template string manual; hasilnya 'Rp 45,000' dan kolom angka bergoyang.
27. **Badge 3D dengan em-dash saat tidak ada model** — Rebuild sering mengganti em-dash dengan badge negatif; hasilnya kolom penuh badge dan menu yang PUNYA 3D tidak lagi menonjol.
28. **Kosakata status tunggal via StatusBadge (dot + label, bukan warna saja)** — StatusBadge dipakai lintas dashboard. Kalau MenuTable dibuat badge sendiri saat rebuild, kosakata status jadi bercabang dan aturan jangan-andalkan-warna bocor.
29. **Baris nonaktif diredupkan dan baris yang diseret jadi transparan** — Peredupan baris nonaktif adalah sinyal utama bahwa menu tidak dilihat pelanggan. Kalau hilang, hanya toggle kecil di kolom Status yang menandainya.
30. **Highlight hover baris hanya di perangkat berpenunjuk** — @media (hover: hover) adalah pengaman kecil yang selalu hilang saat CSS ditulis ulang dengan hover biasa.
31. **Toggle ketersediaan menu langsung dari daftar (optimistic)** — Detail yang hampir pasti hilang: spinner DI DALAM thumb (bukan di samping), minWidth 2.5rem anti-jitter, cursor 'wait', dan label Indonesia 'Habis' (bukan 'Nonaktif'). Perhatikan juga tidak adanya rollback saat error — kalau rebuild menambah rollback, itu perubahan perilaku.
32. **Tombol Edit per baris menuju /dashboard/menu/{id}/edit** — Mengganti Link dengan button onClick router.push menghilangkan prefetch dan navigasi terasa lebih lambat, tanpa gejala error.
33. **Pesan 'tidak ada hasil' terpisah untuk tabel dan kartu** — Kalau digabung dengan empty state utama, user yang sedang mencari akan melihat CTA 'Tambah menu pertama' padahal menunya ada.
34. **Reveal animation panel + hormat prefers-reduced-motion** — Kelas .dash-reveal memakai animation-fill-mode 'both'; kalau CSS-nya hilang tapi kelasnya tetap dipakai (atau sebaliknya), elemen bisa tak pernah muncul. Blok reduced-motion juga sering tidak dibawa.
35. **Modal 'Ekstrak Menu via AI' berbasis portal dengan kunci scroll body** — Pemulihan nilai overflow sebelumnya (bukan hardcode) dan guard 'mounted' adalah detail kode murni; kalau salah, halaman bisa terkunci permanen setelah modal ditutup.
36. **Alur ekstraksi menu dari foto/PDF: idle -> processing -> review -> done** — Progress bar palsu, jeda 320ms sebelum review, dan animasi pemindai adalah perceived-performance yang disengaja untuk proses 10-40 detik. Kalau diganti spinner polos, user akan mengira aplikasi hang.
37. **Editor draf hasil ekstraksi (nama, kategori, harga, deskripsi, hapus item)** — uid() dengan counter (bukan index array) mencegah bug React saat item dihapus di tengah. Filter nama kosong hanya ada di client di sini; tanpa itu user bisa membuat menu tanpa nama.
38. **Penyimpanan massal draf dengan pembersihan dan batas server** — Batas panjang string dan batas 100 item ada di server, jadi rebuild UI tidak akan memecahkannya — tapi pesan error dan tampilan insertedCount ('{n} menu tersimpan!') mudah hilang.

Kalau rebuild UI menelan pesan error mentah jadi 'Terjadi kesalahan', pemilik kehilangan seluruh diagnosis kuota.
40. **Halaman Tambah Menu: konteks kafe, daftar bahan terurut, dan kartu error inventory** — Menyembunyikan form sepenuhnya adalah keputusan sadar — form dengan daftar bahan kosong akan membuat pemilik menyimpan menu tanpa resep tanpa sadar. Rebuild biasanya cuma menampilkan toast dan tetap merender form.
41. **Halaman Edit Menu: penjagaan kepemilikan lewat cafe_id** — Penjagaan otorisasi berlapis (page + server action). Rebuild yang mengambil menu hanya by id akan membocorkan/mengizinkan edit menu kafe lain — celah yang tidak terlihat sama sekali di UI.
42. **Edit Menu: pengambilan paralel inventory + resep + grup varian, dengan dua kartu error berbeda** — Dua kartu error dengan teks berbeda mudah digabung jadi satu 'Gagal memuat data'; diagnosa hilang. Urutan created_at pada resep juga sering hilang sehingga urutan bahan berubah tiap reload.
43. **Varian menu untuk pemilik memuat pilihan nonaktif (berbeda dari tampilan pelanggan)** — Kalau editor rebuild memakai getMenuOptionsForCustomer (activeOnly=true), pilihan yang dimatikan lenyap permanen dan pemilik tidak bisa menyalakannya lagi — kehilangan data yang tidak reversibel dari UI.
44. **Tata letak MenuForm dua kolom dengan pratinjau ponsel di atas pada mobile** — flex-col-reverse disengaja agar user mobile langsung melihat hasilnya; rebuild dengan flex-col biasa menaruh pratinjau di paling bawah dan praktis tak pernah terlihat.

48. **Auto-Isi Detail dengan AI (4 field sekaligus)** — Pengisian selektif (hanya field yang dikembalikan, bukan menimpa semua dengan string kosong) mudah hilang dan bisa menghapus isian manual user.
49. **Kilatan oranye pada field yang baru diisi AI** — Ini satu-satunya penanda field mana yang disentuh AI. Tidak ada toast, tidak ada log. Kalau hilang, user tidak tahu apa yang berubah pada form panjang.
50. **Field dasar menu: wajib isi, tipe, dan placeholder contoh** — Trik value={harga || ""} mencegah '0' menempel di input. Placeholder berbahasa Indonesia dengan contoh nyata juga bagian dari onboarding; keduanya mudah hilang.
51. **Skala default model 3D (slider 0.2x sampai 3.0x dengan pembacaan langsung)** — Rentang, step, minWidth anti-jitter, dan kalimat hint tentang cubit-untuk-zoom mudah hilang; salah rentang membuat model tampil terlalu besar/kecil di AR pelanggan.
52. **Sakelar 'Tampilkan di menu' di dalam form (berbeda dari toggle di tabel)** — Karena nilainya disisipkan manual di handleSubmit (fd.set), bukan lewat <input>, rebuild yang mengganti struktur form dengan mudah kehilangan field ini dan semua menu tersimpan sebagai aktif.
53. **Pemilih hari tersedia (chip Sen sampai Min) dengan pemetaan 1..7** — Pemetaan angka ISO (1=Senin, 7=Minggu) menentukan penjadwalan di halaman pelanggan dan /dashboard/scheduler. Kalau rebuild memakai 0=Minggu (konvensi JS Date), seluruh jadwal menu bergeser satu hari tanpa error apa pun.

62. **Editor Resep Inventory di dalam form menu** — Pencegahan duplikat lewat option disabled (bukan validasi setelah submit) adalah UX yang jauh lebih baik dan mudah hilang; tanpa itu server akan menolak dengan pesan generik setelah user susah payah mengisi form.
63. **Konteks stok per baris resep (Stok / Minimum / status + tautan perbaikan)** — Ambang current_qty <= minimum_qty (bukan <) menentukan kapan peringatan muncul. Tautan kontekstual ke inventory hanya muncul di state 'Habis' — perilaku kondisional yang mudah disederhanakan jadi selalu-tampil atau tidak-pernah-tampil.
64. **Editor Varian & Add-on: tambah/hapus grup dengan batas 10** — Batas 10 ditegakkan di client (tombol), di validator, dan di RPC server. Kalau UI kehilangan batasnya, user baru sadar setelah gagal menyimpan seluruh form.

71. **Urutan penyimpanan berlapis: menu -> resep -> varian, dengan pemulihan anti-duplikat** — Ini pertahanan terhadap duplikasi data yang tidak terlihat sama sekali di UI. Rebuild yang menggabungkan semuanya jadi satu server action, atau membuang state createdMenuId, akan menghasilkan menu ganda setiap kali user mencoba lagi setelah error.
72. **Tombol simpan dengan label kontekstual dan penguncian sub-editor** — Penerusan disabled ke dua editor anak mencegah user mengubah data yang sedang dikirim. Sangat mudah tidak dibawa saat komponen diganti, dan bug-nya berupa data yang tersimpan tidak sesuai yang terlihat.
73. **Hapus menu dengan konfirmasi native menyebut nama menu** — Nama menu di dalam konfirmasi adalah pengaman terakhir agar user tidak menghapus menu yang salah. Kalau confirm() diganti dialog kustom saat rebuild, pastikan namanya tetap ikut — dan pastikan router.refresh() setelah push tetap ada, kalau tidak daftar masih menampilkan menu yang sudah terhapus.
74. **Default dan pembersihan payload menu di server (menuPayload)** — Perbedaan null vs string kosong terlihat sepele tapi dipakai kode lain (Badge3D memakai !!model_3d_url). Aturan !== 'false' juga berarti semua bug pengiriman field berujung aktif — perilaku fail-safe yang disengaja.
75. **Peta revalidatePath setiap server action menu** — revalidatePath('/[slug]', 'page') pada reorderMenus adalah satu-satunya penghubung ke sisi pelanggan. Kalau hilang, pemilik menyusun ulang menu dan pelanggan tetap melihat urutan lama selama berjam-jam — tanpa error apa pun.
76. **Penjagaan kepemilikan pada semua server action menu** — Filter cafe_id ganda pada UPDATE/DELETE adalah pertahanan utama multi-tenant. Rebuild yang menulis ulang action untuk menyederhanakan bisa membuangnya, dan tidak ada test UI yang akan menangkapnya.
77. **Pemetaan error RPC resep dan varian ke pesan Bahasa Indonesia** — Terjemahan kode RPC ke Bahasa Indonesia hanya ada di server action ini. Kalau rebuild memakai RPC langsung dari client atau membuang mapping-nya, pemilik kafe akan melihat pesan Postgres yang tidak bisa dimengerti.
78. **Gaya input dan fokus konsisten dashboard (dash-input, dash-press, dash-btn)** — outline:none pada dash-input WAJIB disertai box-shadow pengganti — kalau tidak, pengguna keyboard kehilangan indikator fokus sepenuhnya. Ketidakkonsistenan hardcode vs variabel CSS juga harus disatukan secara sadar, bukan diam-diam.
79. **Label tersembunyi (sr-only) dan aria-label kontekstual di editor varian & resep** — Grid tanpa label terlihat adalah bentuk yang paling sering di-rebuild ulang, dan sr-only hampir selalu ikut hilang — hasilnya panel varian menjadi tidak dapat dipakai dengan screen reader tanpa gejala visual apa pun.
