### Risiko saat rebuild — A. Shell & navigasi

1. **Gerbang auth server-side di layout dashboard** — Saat rebuild orang sering memindahkan guard ke client component atau mengandalkan middleware saja; hasilnya flash shell kosong sebelum redirect, dan owner yang belum punya kafe bisa ikut ter-redirect padahal seharusnya masuk.
2. **Middleware guard rute + redirect balik dari /login** — Rebuild UI biasanya tidak menyentuh middleware, tapi kalau path rute dashboard diubah (mis. jadi /app/*), matcher jadi tidak cocok dan seluruh dashboard terbuka tanpa auth.
3. **Satu lookup auth+kafe per request lewat React cache()** — Kalau shell baru mengambil data kafe sendiri (mis. lewat fetch client di sidebar) alih-alih menerima props dari layout, dedupe cache() hilang diam-diam: tidak ada yang error, halaman cuma jadi 2-3x lebih lambat dan kuota Supabase naik.
4. **Degradasi anggun saat owner belum punya kafe (cafe = null)** — Sangat mudah hilang: rebuild biasanya menulis `cafe.nama_cafe` langsung tanpa optional chaining, lalu shell crash total untuk akun baru — dan kasus ini tidak pernah muncul di akun testing yang sudah punya kafe.
5. **Registry navigasi 8 rute dengan label Indonesia + ikon Lucide** — Rebuild sering mengelompokkan nav jadi section ('Analisis', 'Operasional') dan diam-diam menjatuhkan satu item — Inventory dan Pengumuman paling sering hilang karena jarang dipakai saat demo.
6. **Field `desc` per item nav (saat ini tidak dirender)** — Ini fitur 'hanya terlihat di kode'. Rebuild akan menghapusnya karena terlihat dead code, padahal ini copy bahasa Indonesia yang sudah dikurasi dan mahal untuk ditulis ulang.
7. **Pencocokan rute aktif: exact untuk root, prefix untuk sub-rute** — Implementasi naif pakai startsWith tanpa flag exact akan membuat Analitik ikut aktif di semua halaman. Sebaliknya pakai === saja akan membuat item Menu mati saat berada di halaman edit menu — sub-rute /dashboard/menu/new dan /dashboard/menu/[id]/edit memang ada (lihat direktori app/dashboard/menu).
8. **Indikator pending navigasi + pulse ikon** — Ini satu-satunya umpan balik bahwa klik terdaftar pada koneksi lambat. Rebuild yang mengganti nav dengan komponen shadcn Sidebar akan kehilangan pendingHref, aria-busy, dan animasi navPulse sekaligus — dan tidak akan terlihat di localhost yang instan.
9. **Reset state saat pindah rute (pola derive-state-during-render)** — Kalau dipindah ke useEffect, akan ada satu frame di mana UI lama masih terlihat; kalau kondisinya salah (tanpa penjaga lastPath !== pathname) React akan infinite-render. Perilaku 'sheet menutup sendiri saat back button' hampir tidak pernah masuk daftar tes manual.
10. **Prefetch semua rute nav setelah mount + prefetch per Link** — Menghilang tanpa jejak visual. Efeknya cuma 'dashboard terasa lebih lambat' — tidak ada error, tidak ada tes yang gagal, dan tidak akan terasa di localhost.
11. **Judul + ikon header mengikuti rute aktif, dengan fallback** — Ini satu-satunya <h1> di seluruh dashboard shell (halaman anak memakai DashboardPageHeader yang juga <h1> — ada dua h1 per halaman, perilaku existing yang harus dicatat). Rebuild yang mengganti dengan breadcrumb otomatis akan kehilangan fallback NAV[0] dan menampilkan judul kosong di rute yang belum terdaftar.
12. **Sidebar desktop sticky, lebar tetap 236px, tinggi 100dvh** — Angka 236px dan 100dvh terlihat sembarang jadi mudah 'dibulatkan' ke w-64/100vh. 100vh akan membuat footer sidebar (tombol Keluar) tertutup address bar di Safari iOS saat sheet dibuka.

Tooltip di tombol yang lg:hidden juga terlihat tidak berguna sehingga gampang dibuang, padahal ia jadi label yang terlihat untuk pengguna tablet.

Warna #5A7898 juga hardcoded (bukan var(--dash-muted) padahal nilainya identik); kalau token diubah, tombol ini tertinggal.

Kalau Toaster dipindah ke root layout, ia keluar dari scope token dashboard dan semua toast berubah jadi kartu putih terang di atas kanvas gelap.

Atau sebaliknya, menghapus useTheme dan mengunci theme='dark' akan mengubah kontras di sistem light.

Menghapus div-nya tidak menyebabkan crash — semua portal cuma diam-diam jatuh ke body dan berubah jadi putih. Menamai ulang ID akan memutus kelimanya sekaligus.
24. **Adapter token shadcn khusus scope dashboard** — Kalau rebuild memindahkan override ini ke :root 'supaya lebih sederhana', seluruh halaman menu pelanggan ikut berubah gelap. Kalau kelas .dash-root dihapus dari wrapper, setiap tombol dashboard mendadak jadi hitam-putih.

26. **Font Poppins untuk seluruh permukaan dashboard (dobel: inline + CSS)** — Pengulangan inline style terlihat mubazir dan akan 'dibersihkan', tapi salah satunya menjaga konten portal. Perhatikan juga bahwa font --font-jakarta dimuat di root layout tapi dashboard justru memakai Poppins — rebuild yang 'membetulkan' ini ke Jakarta akan mengubah seluruh tipografi dashboard.
27. **Header aplikasi sticky dengan backdrop blur** — z-30 adalah angka yang harus berkoordinasi dengan overlay Radix (z-50 di dialog/sheet/popover/tooltip). Kalau header dinaikkan ke z-50 saat rebuild, ia akan menutupi overlay modal. Nilai rgba(6,14,27,0.85) juga hardcoded — kalau --dash-canvas berubah, header jadi belang.

Rebuild biasanya mengganti kedelapannya dengan satu <Spinner /> bersama — tidak ada tes yang gagal, tapi setiap perpindahan halaman berubah dari transisi mulus jadi layar kosong berkedip. Perbedaan max-width per rute juga membuat skeleton meloncat kalau disamakan.
30. **Animasi shimmer skeleton dashboard** — Angka 720px background-size harus tepat dua kali jarak geser 360px agar loop terlihat mulus; salah salah satunya menghasilkan kedipan tiap siklus. Ganti ke animate-pulse Tailwind akan terlihat 'sama saja' di screenshot tapi terasa berbeda saat berjalan.

Perhatikan juga varian destructive di sini soft — ConfirmAction sengaja MENIMPANYA dengan inline style merah penuh (ConfirmAction.tsx:50); kalau salah satunya diubah, konfirmasi hapus kehilangan bobot visualnya.
46. **Overlay dan animasi masuk/keluar bawaan primitive (pemilik tunggal motion)** — Sangat mudah 'ditingkatkan' dengan Framer Motion, yang justru menabrak state data-open/data-closed Radix dan membuat animasi keluar terpotong. Arrow tooltip juga sering hilang karena bukan bagian dari shadcn versi lama.
47. **Collapsible primitive tersedia sebagai bagian sistem** — Karena tidak punya styling, komponen ini terlihat 'kosong' dan gampang dianggap tidak terpakai lalu dihapus — memutus impor di halaman yang memakainya. Atribut data-slot juga jadi hook untuk selector CSS turunan.

49. **Cache PWA runtime yang mempengaruhi kesegaran navigasi dashboard** — Perilaku ini hanya ada di produksi sehingga tak pernah terlihat saat rebuild. StaleWhileRevalidate berarti owner bisa melihat data dashboard lama sekejap setelah update — kalau shell baru menambah indikator 'data per pukul X', ia harus sadar konten bisa berasal dari cache. urlPattern juga memaku domain 3diner.vercel.app; domain kustom baru tidak akan ter-cache.

### Risiko saat rebuild — B. Analitik — /dashboard

1. **Guard autentikasi + redirect ke /login** — Saat rebuild sering dianggap 'sudah dijaga layout' lalu guard di page dihapus. Kalau layout di-refactor jadi client component, guard hilang total dan halaman render dengan data null.
2. **Dedupe query auth + kafe via React cache()** — cache() sangat mudah hilang saat file dipecah atau fungsi dijadikan biasa. Gejalanya bukan error, hanya 3-4x query per halaman — tidak terlihat di UI sama sekali.
3. **Pengambilan data paralel (analytics + inventory + today)** — Rebuild sering mengubahnya jadi tiga await berurutan karena lebih mudah dibaca. Tidak ada gejala fungsional, hanya halaman jadi lambat.
4. **Empty state 'Belum ada kafe terhubung'** — Jalur ini jarang dites karena akun dev selalu punya kafe. Kalau hilang, user baru melihat error TypeError saat destructuring data.
5. **Skeleton loading khusus halaman analitik** — loading.tsx adalah file terpisah dari page.tsx; rebuild yang fokus ke page.tsx akan meninggalkan skeleton lama yang bentuknya tidak cocok lagi, atau file terhapus tanpa disadari.
6. **Animasi shimmer skeleton gelap (.dash-skel)** — Kelas utility di globals.css mudah dianggap sampah saat CSS dibersihkan, apalagi kalau rebuild pindah ke Tailwind/shadcn skeleton.
7. **Reveal bertahap per blok (dash-reveal + dash-d1..d5)** — Kelas urutan dash-d1..d5 gampang tertukar atau tidak ikut disalin ke markup baru. Hasilnya animasi ada tapi ritmenya hilang — perubahan halus yang tidak akan dilaporkan sebagai bug.

### Risiko saat rebuild — C. Penjualan — /revenue

1. **Metadata judul tab halaman** — Saat file page dirombak jadi client component, `export const metadata` ilegal dan biasanya dihapus diam-diam tanpa diganti generateMetadata.
2. **Penjagaan sesi: redirect ke /login** — Rebuild yang memindahkan fetching ke client akan membuat guard ini hilang atau baru jalan setelah data terlanjur ter-render.
3. **Dedupe query auth + kafe lewat React cache()** — Sangat mudah hilang: memanggil createClient()/supabaseAdmin langsung di komponen baru tidak memicu error apa pun, hanya menggandakan query tanpa gejala visual.
4. **Rentang tanggal lewat URL searchParams (start & end)** — Rebuild yang memindahkan rentang ke useState lokal memutus deep-link, tombol Back, dan sinkronisasi ke ExportReport sekaligus — tampak "masih jalan" saat dicoba manual.
5. **Skeleton loading khusus halaman penjualan** — File loading.tsx terpisah dari page.tsx, jadi saat page dirombak skeleton ini tidak ikut diperbarui dan menghasilkan layout shift yang tidak disadari.
6. **Animasi shimmer skeleton** — Diganti skeleton bawaan library (pulse) yang timing dan arahnya beda dari sisa dashboard.
7. **Empty state seluruh halaman saat kafe/data tidak ada** — Sering diganti "return null" atau satu baris teks; yang paling mudah hilang adalah fakta bahwa tombol aksi tetap dirender di state kosong ini.
8. **Subtitle header dinamis 4 varian rentang** — Cabang "hanya start" dan "hanya end" nyaris tak pernah dicoba manual — biasanya rebuild hanya menyisakan dua cabang.
9. **Format tanggal & angka locale id-ID pada subtitle** — Rebuild sering memakai Intl default browser atau date-fns locale en, yang diam-diam mengubah "Agu" jadi "Aug" dan "1.234" jadi "1,234".
10. **Slot aksi header: urutan Ekspor lalu DateRangePicker** — Urutan tombol mudah tertukar saat rebuild, dan varian actions untuk state kosong sering dilupakan.
11. **Reveal bertahap tiga baris konten (dash-d1/d2/d3)** — Delay class dash-d1..d3 tampak dekoratif dan sering dibuang; hilangnya menghasilkan "pop" serentak yang terasa berbeda dari halaman dashboard lain.
12. **Hormat prefers-reduced-motion** — Animasi baru berbasis JS (Framer Motion) tidak otomatis tunduk pada media query ini — konten bisa jadi permanen invisible bagi pengguna reduced-motion.
13. **KPI Total Pendapatan dengan delta mingguan kondisional** — Logika kondisional satu baris ini paling sering disederhanakan jadi selalu tampil, sehingga menampilkan perbandingan yang salah secara statistik pada rentang kustom.
14. **Perhitungan revenueDelta (minggu ini vs minggu lalu)** — Pembagian nol mudah terlewat saat rumus ditulis ulang, menghasilkan "Infinity%" atau "NaN%" yang hanya muncul pada kafe baru.
15. **KPI Jumlah Pesanan dengan caption adaptif** — Caption dua-varian ini sangat kecil dan biasanya di-hardcode jadi satu string saat rebuild.
16. **KPI Rata-rata / Pesanan** — Guard pembagian nol hilang saat rumus dipindah ke client/useMemo.
17. **KPI Item Terjual** — Guard Array.isArray sering dianggap defensif berlebihan dan dibuang, padahal items berasal dari endpoint publik POST /api/orders.
18. **Animasi count-up angka KPI** — Diganti angka statis karena "tidak fungsional"; padahal ini penanda visual bahwa data sudah masuk.

79. **Menu ekspor di-portal dengan guard hydration** — Guard `mounted` tidak punya efek visual apa pun; hilangnya baru memunculkan error hydration di production build.
80. **Menu ekspor mengikuti scroll dan resize** — Flag capture:true pada listener scroll adalah detail satu kata yang menentukan apakah menu ikut bergerak di dalam shell dashboard yang punya overflow sendiri.
81. **Tutup menu ekspor dengan klik luar** — Menu ini tidak punya penutup Escape (berbeda dari DateRangePicker), jadi klik-luar adalah satu-satunya jalan keluar; kalau pengecekan ref ganda disederhanakan, menu bisa terkunci terbuka atau tertutup sebelum klik terdaftar.
82. **Animasi masuk menu ekspor (keyframe inline)** — Keyframe didefinisikan lokal di komponen (bukan globals.css); memindahkan markup tanpa membawa tag <style> membuat animasi diam-diam mati.
83. **Dua baris aksi ekspor: CSV dan Cetak/PDF** — Sub-teks deskriptif ini adalah satu-satunya penjelas apa bedanya kedua opsi; sering dipangkas jadi menu satu-baris.
84. **Spinner per-jenis ekspor dan penguncian tombol** — Disederhanakan jadi satu boolean loading global, sehingga tidak lagi terlihat aksi mana yang berjalan.
85. **Pesan error ekspor inline di dalam menu** — Diganti toast global; padahal desainnya sengaja inline agar konteksnya jelas dan user bisa langsung mencoba format lain.
86. **Guard rentang kosong sebelum mengunduh** — Bila guard hilang, user mendapat file kosong atau dialog cetak kosong yang membingungkan — dan tidak akan dianggap regresi karena "tetap jalan".
87. **Menu ekspor hanya tertutup saat berhasil** — Blok finally hilang → tombol terkunci selamanya setelah satu kegagalan, hanya bisa dipulihkan dengan reload.
88. **Server action getSalesExport: scoping kepemilikan & batas 2000 baris** — Batas 2000 tanpa notifikasi adalah jebakan diam: kafe besar akan mendapat laporan tidak lengkap. Scoping cafe_id adalah kontrol keamanan multi-tenant yang tidak boleh hilang.
89. **Filter tanggal ekspor dengan validasi isNaN** — Penyetelan 23:59:59.999 mudah lupa; akibatnya seluruh transaksi hari terakhir raib dari laporan tanpa pesan error apa pun.
90. **Normalisasi baris ekspor (items_summary & item_count)** — Semua fallback ini melindungi dari data kotor endpoint publik; hilangnya menghasilkan sel berisi "undefined"/"NaN" di laporan yang dibuka pemilik kafe.
91. **Guard CSV injection pada csvCell** — Ini kontrol keamanan tanpa jejak visual: laporan tetap "terlihat benar" setelah guard dihapus. table_number dan items_summary berasal dari endpoint pemesanan publik, jadi hilangnya guard membuka eksekusi formula di mesin pemilik kafe.
92. **Struktur file CSV: BOM, blok metadata, header 9 kolom** — BOM satu karakter tak terlihat; hilangnya membuat nama menu beraksen jadi mojibake di Excel Windows — dan nama kafe pun melewati csvCell (ada tes khusus untuk itu).
93. **Nama file unduhan CSV dan pembersihan objectURL** — Pola nama file dan revokeObjectURL keduanya tidak terlihat di UI; ekspor berulang tanpa revoke membocorkan memori tab.
94. **Cetak/PDF lewat iframe tersembunyi dengan timing khusus** — Jeda 400ms adalah waktu tunggu agar layout iframe siap sebelum print; menghapus/mengubahnya menghasilkan halaman cetak kosong yang hanya muncul di sebagian browser.
95. **Escaping HTML pada laporan cetak** — HTML dirakit sebagai template string lalu ditulis via document.write ke iframe same-origin — satu interpolasi tanpa escapeHtml langsung menjadi XSS di sesi pemilik kafe. Rebuild yang mengganti string template dengan JSX/react-pdf harus tetap membuktikan properti ini.
96. **Isi laporan cetak: header, tiga kartu ringkasan, tabel 8 kolom** — Kartu "Sudah Lunas x/y" adalah satu-satunya indikator piutang di laporan cetak dan tidak punya padanan di layar — hilang tanpa jejak.
97. **Perbedaan kolom CSV vs PDF (perilaku baseline)** — Rebuild yang "menyeragamkan" dua format akan mengubah isi dokumen yang mungkin sudah dipakai untuk arsip/pembukuan.
98. **Gaya cetak A4 dan aturan @media print** — Aturan @page hanya terlihat di dialog cetak; hampir tidak pernah diuji ulang setelah rebuild.
99. **Baris TOTAL dan pesan kosong pada laporan cetak** — Cabang kosong tidak bisa dicapai lewat UI (diblokir guard rows.length===0), jadi mudah dianggap kode mati dan dihapus — padahal fungsi ini diekspor dan diuji terpisah.
100. **Label rentang & tanggal-waktu pada berkas ekspor** — Empat varian rangeLabel diduplikasi terpisah dari logika subtitle halaman; rebuild yang menyatukannya bisa diam-diam mengubah kapitalisasi atau melewatkan satu varian.
101. **Peta label metode & status pembayaran untuk ekspor** — Peta ini terpisah dari META StatusBadge di layar; keduanya harus konsisten agar laporan cocok dengan dashboard, tapi tidak ada apa pun yang memaksa sinkronisasi itu.
102. **Revalidasi halaman penjualan saat pesanan tunai dilunasi** — Baris revalidatePath ini hidup di file lain (dashboard-actions.ts), jadi rebuild UI revenue tidak akan menyentuhnya — tapi mengganti data fetching ke client-side membuat mekanisme ini tidak berguna dan halaman jadi basi tanpa gejala.
103. **Prefetch rute Penjualan dari shell dashboard** — Prefetch dan penanda pending nav tidak terlihat sebagai fitur; hilangnya hanya terasa sebagai "dashboard jadi lambat" tanpa penyebab jelas.
104. **Fokus keyboard terlihat (focus-visible oranye)** — Jumlah tab stop kalender yang besar, ketiadaan roving-tabindex, dan ketiadaan focus trap/restore adalah baseline nyata; rebuild dengan komponen library bisa mengubah urutan fokus, menghilangkan cincin oranye khas brand, atau menambah focus trap yang belum pernah ada.
